# 小红书笔记助手 v2.0 需求清单

版本：v1  
日期：2026-05-15  
产品定位：面向餐饮、酒旅本地生活老板的“小红书到店种草笔记生产工具”

## 1. 总体修正方向

当前网页的基础流程没有大问题：采集标题、员工筛选、生成文案、上传图片、生成素材包、红线审核、手动发布，这条链路是成立的。

真正需要重做的是内核：

1. 标题来源不能只靠大模型编。  
   如果没有真实小红书参考池，所谓“30 个热门标题”大概率只是模型套话，不是真实平台正在流行的内容结构。

2. 图片工厂不能只是“调色 + 加字”。  
   小红书图文的核心不是精致海报，而是“真实实拍 + 情绪花字 + 场景信息 + 轻贴纸 + 收藏价值”。老板上传的图要被做成能直接发的图，而不是给一堆建议。

3. 图片处理不应全部调用混元图像。  
   调色、裁切、排版、贴纸、价签、手写花字、九宫格拼图都可以用前端 Canvas 完成，速度快、成本低、可控。混元更适合做：文案生成、图片识别、图文匹配判断、红线扫描。

v2.0 的方向是：

- 数据层：真实参考池 + 大模型二次改写
- 文案层：真实用户口吻 + 少量 emoji + 避免广告腔
- 图片层：Canvas 套版器 + 花字贴纸库 + 自适应调色
- 审核层：事实审核 + 红线审核 + 图文匹配检测

## 2. 数据采集模块改造

### 2.1 数据源策略

优先级从高到低：

1. 人工导入真实参考池  
   员工从小红书手动收集优质笔记标题、正文、封面截图、互动数据，整理成表格导入。

2. 第三方数据平台  
   如新红、千瓜、灰豚等，价格、接口额度、是否允许商用需调研。

3. 手动 URL 解析  
   员工粘贴公开笔记链接，系统只保存标题、正文摘要、结构标签，不复制图片。

4. 大模型补充生成  
   仅在没有足够参考池时兜底，不能标成“热门”。

### 2.2 参考池字段

建议表格字段：

| 字段 | 说明 |
| --- | --- |
| platform | 小红书 / 抖音 |
| industry | 餐饮 / 酒旅 |
| city | 城市 |
| keyword | 关键词 |
| title | 原始标题 |
| body_excerpt | 正文摘要 |
| cover_style | 封面类型 |
| note_structure | 笔记结构 |
| likes | 点赞 |
| collects | 收藏 |
| comments | 评论 |
| publish_date | 发布时间 |
| tags | 标签 |
| risk_note | 是否有不可复用风险 |

### 2.3 采集规则

采集时不追求全站热点，而是围绕“本地生活转化型”：

- 酒旅：海景、民宿、亲子房、情侣出行、周末放空、节假日、提前预约、避坑
- 餐饮：新品、招牌菜、套餐、人均、排队、隐藏菜单、适合聚餐、适合约会

输出不是“热点标题”，而是：

- 真实参考标题
- 参考结构
- 可改写方向
- 适合的图片类型
- 员工是否建议采用

## 3. 选题生成模块改造

### 3.1 两步法

第一步：从真实参考池选出 10-30 条相似笔记。  
第二步：让混元基于这些参考进行二次改写。

不能让模型凭空生成“热门标题”，而是让模型回答：

- 这些参考内容共同用了什么钩子？
- 哪些适合当前商家？
- 如何改成不撞文案的新标题？
- 哪些标题更可能带来收藏/咨询/预约？

### 3.2 标题生成要求

标题必须像真实用户：

- “威海这家海景民宿，真的有点舒服”
- “七夕住这里也太会了吧”
- “这家店我愿意二刷”
- “人均不高但体验感很满”
- “来之前先看这篇，少踩坑”

避免：

- “高转化爆款标题”
- “三步打造门店增长”
- “本地生活商家必看”
- “教你实现私域转化”

### 3.3 选题输出字段

```json
{
  "title": "七夕住这里也太会了吧",
  "source_style": "真实体验日记",
  "reason": "适合酒旅节日场景，能承接预约咨询",
  "image_need": ["窗景", "卧室", "客厅", "周边"],
  "risk": "需人工确认价格和预约规则"
}
```

## 4. 图片工厂模块改造

图片工厂是 v2.0 的重点。

目标不是做“AI 生图”，而是把老板上传的真实照片做成能发的小红书图文素材。

### 4.1 上传与识别

用户上传图片后，系统先做两层识别：

第一层：前端基础识别

- 横图 / 竖图 / 方图
- 明暗程度
- 分辨率
- 是否适合裁成 3:4

第二层：混元视觉识别

- 图片内容：卧室、窗景、客厅、菜品、门头、菜单、团购截图等
- 适合用途：封面、环境页、价格页、预约页、避坑页
- 不适合写什么：例如窗景图不要写“房间很大”，菜单图不要写“环境好”

输出示例：

```json
{
  "index": 1,
  "scene": "窗景",
  "description": "室内窗边可以看到城市和天空，画面明亮",
  "usable_for": ["封面", "氛围页", "位置页"],
  "caption_hint": "海景好治愈",
  "avoid": "不要写床品、菜品或菜单信息"
}
```

### 4.2 智能调色

前端 Canvas 处理，不依赖混元图像。

酒旅图片：

- 提亮
- 增加通透感
- 轻微降黄
- 保留真实窗光
- 不要过度磨皮或假高级感

餐饮图片：

- 食物轻微增饱和
- 暖色提升
- 适度增强对比
- 保留真实桌面环境

菜单/团购截图：

- 提高清晰度
- 不做滤镜
- 只做裁切和信息框

### 4.3 套版器

套版由前端 Canvas 完成。

单图模板建议 5 种：

1. 透明大字封面  
   适合窗景、菜品、门头。

2. 角落手写标注  
   适合房间细节、菜品细节。

3. 收藏清单图  
   适合菜单、团购截图、预约规则。

4. 氛围日记图  
   适合酒旅、咖啡、甜品。

5. 对比选择图  
   适合套餐、人均、房型对比。

九宫格模板建议 3 种：

1. 一张大封面 + 八张细节  
2. 三列场景流：外观 / 环境 / 产品  
3. 收藏攻略流：封面 / 价格 / 路线 / 避坑 / 体验

四宫格模板建议 3 种：

1. 封面 + 三个卖点  
2. 价格 + 环境 + 产品 + 预约  
3. 适合谁 / 怎么订 / 到店看什么 / 注意什么

### 4.4 花字和贴纸库

先做内置文字贴纸，后续可采购版权素材。

酒旅类：

- 好温馨啊
- 住得太舒服了
- 海景好治愈
- 老板人很好
- 下次还想来
- 姐妹们放心冲
- 氛围感拉满

餐饮类：

- 巨巨巨好吃
- 种草了姐妹们
- 强烈推荐
- 这家真的可
- 好吃到想打包
- 闭眼点不踩雷
- 这一口绝了

通用类：

- 收藏备用
- 少踩坑
- 先看这篇
- 真的值
- 适合周末
- 可以二刷

### 4.5 图文匹配检测

生成后做一次匹配检测：

- 文案说海景，图片里是否有海/窗景？
- 文案说卧室舒服，图片是否是卧室？
- 文案说价格/套餐，是否有菜单/团购截图或用户填写价格？
- 文案说老板人很好，是否属于主观体验，不应伪造具体事件？

输出：

```json
{
  "passed": true,
  "issues": [],
  "fix": "可发布，价格和预约规则仍需人工确认"
}
```

## 5. UI/交互优化

### 5.1 流程简化

建议流程：

1. 选择行业：餐饮 / 酒旅
2. 填写店铺信息
3. 上传图片
4. 系统识别图片
5. 选择参考标题
6. 生成文案 + 成品图
7. 员工审核
8. 下载发布素材包

### 5.2 进度提示

生成时展示阶段：

- 正在识别图片
- 正在匹配图文
- 正在生成文案
- 正在套版成图
- 正在红线扫描

### 5.3 草稿保存

本地保存：

- 店铺信息
- 上传图片
- 已生成文案
- 成品图
- 审核状态

## 6. 模型调用策略

混元适合做：

- 文案生成
- 图片识别
- 图文匹配判断
- 红线扫描
- 参考标题改写

前端 Canvas 适合做：

- 图片调色
- 裁切
- 套版
- 加字
- 贴纸
- 导出 JPG

不建议混元做：

- 每张图都图生图
- 中文文字直接生成在图片里
- 固定排版

原因：

- 成本高
- 速度慢
- 中文字容易错
- 可控性差

## 7. 可复用 Prompt 模板

### 7.1 选题改写 Prompt

```text
你是小红书本地生活内容策划。
用户是{行业}老板，店铺信息是：{店铺信息}。
以下是真实参考标题和结构：{参考池}。

请不要照抄参考内容，而是提炼它们的钩子和结构，生成 20 个适合当前商家的小红书标题。

要求：
1. 像真实用户，不要像广告。
2. 不要使用“爆款、引流、转化、私域、成交”等后台词。
3. 标题要适合收藏、咨询、预约。
4. 输出 JSON。
```

### 7.2 文案生成 Prompt

```text
你是小红书真实用户口吻写手。
行业：{行业}
店铺信息：{店铺信息}
选题：{标题}
图片识别结果：{图片识别结果}

请生成一篇小红书笔记。

要求：
1. 像真实体验，不要像商家广告。
2. 可以自然使用 5-10 个 emoji。
3. 不夸大效果，不承诺最低价、爆单、官方身份。
4. 结尾引导评论区咨询，不引导站外。
5. 同时输出 images 数组，每张图必须指定 photo_index。
```

### 7.3 图片识别 Prompt

```text
你是小红书本地生活图片编辑。
请阅读用户上传的每张图片，判断它拍的是什么，适合做哪一页图文。

输出 JSON：
{
  "items": [
    {
      "index": 1,
      "scene": "窗景/卧室/客厅/菜单/门头/菜品/团购截图/其他",
      "description": "一句话描述真实画面",
      "usable_for": ["封面", "环境页"],
      "caption_hint": "适合压在图上的短句",
      "avoid": "不要写什么"
    }
  ]
}
```

### 7.4 红线扫描 Prompt

```text
请扫描以下小红书笔记是否存在风险。

重点检查：
1. 是否声称官方身份
2. 是否承诺效果
3. 是否诱导站外导流
4. 是否虚构价格、地址、案例
5. 是否出现极限词

输出 JSON：
{
  "passed": true,
  "risk_terms": [],
  "suggestions": []
}
```

## 8. 上线优先级

第一阶段：

- 修复文案 JSON 解析
- 图片导出真正 JPG
- 前端 Canvas 套版
- 内置花字库
- 基础调色

第二阶段：

- 混元视觉识别图片
- photo_index 图文匹配
- 图文匹配检测

第三阶段：

- 真实参考池导入
- 第三方数据源调研
- 员工审核后台
- 草稿管理

## 9. 备注

- 第三方数据平台价格、额度、接口合法性需调研。
- 字体、贴纸、花字素材如用于商业发布，需要采购版权或使用可商用素材。
- 真实小红书内容不能直接复制，只能做结构参考和二次改写。

## 附录：图片工厂风格纠正 Prompt

以下规则优先级最高，用于约束 Codex 改造图片工厂：

1. 彻底删除所有功能型标签胶囊。  
   不要出现“真实体验 / 不是广告 / 收藏备用 / 到店清单 / 预约提醒 / 路线清单 / 适合周末”等圆角矩形标签。

2. 删除自制页码角标。  
   小红书 App 自带翻页提示，图片本身不要写“5/8、6/8”。

3. 删除按钮式贴纸。  
   不要出现黄色按钮、“建议收藏”按钮、绿色对勾系统提示。

4. 图片文字风格要轻。  
   每张图只保留 1-2 个文字焦点。文字可以贴边、斜放、靠主体，不要居中规整，不要堆满。

5. 字体方向：现代瘦体或手写感。  
   可优先使用系统可用的楷体/手写感字体兜底，如 KaiTi、STKaiti、LXGW WenKai；后续如商用需要采购字体版权，例如得意黑、字制区喜脉体、汉仪文黑、阿里妈妈刀隶体等。

6. 颜色方向：与图片融合。  
   优先米白、淡粉、淡黄、深棕。严禁红色粗描边字，严禁像横幅广告。

7. 装饰元素要轻。  
   可以用 🤍 ✨ 📍 🛏️、细线、手绘小箭头、轻圈线；不要用大色块、功能按钮、系统提示图标。

8. 图片处理走前端 Canvas。  
   调色、裁切、套版、加字、拼图、JPG 导出默认使用 Canvas，混元只负责文案、图片识别、图文匹配判断。
